# 应急物资保障 SupplyGuard

> 校园极端天气演练的「保供值班员」：不是告诉你仓库里有多少箱水，是告诉你**每个关键服务点的保障任务到底成不成立**。

核心差异点：**签收失败 ≠ 未送达**——投送单派出去、现场却没能留下签收凭证，这箱水到底到没到？系统判「待验证」，不武断算缺口。

## 快速开始（3 分钟）

```bash
pip install -r requirements.txt
# 下载失败换镜像：pip install -i https://mirrors.aliyun.com/pypi/simple/ -r requirements.txt
cd backend && uvicorn main:app --reload --port 8000
# 浏览器打开 http://localhost:8000
```

首页应看到 3 个关键服务点的物资状态表。点「运行保障分析」生成一次 `run_id`；点「模拟签收取证失败」观察 T-001 从「在途」转为「待验证」。

## 教学场景规模（固定，不放大）

| 项 | 数量 |
|---|---|
| 关键服务点 | 3 个（教学楼 A / 图书馆 / 体育馆） |
| 储备点 | 2 个（物资仓库 1 / 2） |
| 教学物资 | 3 类（饮用水 / 应急照明 / 急救包） |
| 在途投送单 | 3 张（T-001 / T-002 / T-003） |

不引入车辆路径优化、动态库存、多智能体——**业务机制真实，教学模型有限**。

## 核心设计原则

**签收取证失败 ≠ 未送达。** 状态标「待验证」，需补取证后再下结论，不直接计入缺口。
**先计算，再解释：** LLM 只解释结构化结果，不直接判定保障状态。
**缺口 = 需求 − 已到位 − 在途。**
